# v0.460.0

This build consolidates the local changes made after v0.453.0. Intermediate version numbers are intentionally skipped. It focuses on reliable conversation input, readable long transcripts, session-owned background work, OAuth state, and file delivery.

## 中文更新说明

### 输入、附件与长会话

- 模型忙时默认排队，支持排序、编辑、取回、单条删除、清空和逐条发送。发送过程绑定原会话，附件预处理期间撤回有效，避免切会话误投和自动/手动双发。
- 首字输出前也能停止。停止释放运行实例后，切换推理强度可按需恢复实例，不需要先让模型回复一轮；保存状态和失败原因可见。
- 更早的用户消息可编辑并重新执行，补齐新粘贴图片、删除全部附件和多图补读的语义。图片与文档统一预览，保留未确认发送和失败重试状态。
- 首屏缺少最近提问、工具过程折叠后不足一屏或滚到顶部时可继续加载历史。补页有预算、去重、游标和过期请求保护，不会无限自动翻页。
- 按正在阅读的消息保持滚动位置，修正整页高度差补偿、残留快照、虚拟列表间距和重新测高导致的抽动。正在阅读的过程不会在停流时突然收起，正常贴底和显式跳转保留。

### 后台与自动化

- 支持将当前工作交给隔离后台会话继续，并继承父会话权限。交接等父回合和 SDK 真正空闲；停止失败或超时则取消，避免父子同时操作同一工作。
- 后台结果按具体运行批次登记消费。主动读取完整结果后不再重复回传，实例后续新一轮结果不被误吞；截断或身份不确定的结果不自动确认。
- 会话定时与巡查分区，定时结论固定到来源会话的相应回合。修复状态残留、多个定时互相覆盖结论、人工确认卡被折叠和旧循环重试覆盖停止状态。
- 已结束活动历史滚动保留七天、最多一百条。启动、访问列表和写入时清理；运行中不参与淘汰，不删除任务配置或生成的工作产物。

### OAuth、模型与交付

- Grok OAuth 的共享客户端版本标记更新至 `1.0.13`，修复服务端拒绝旧 `0.2.95` 的 HTTP 426。聊天、用量查询和原生搜索共用新标记；已用现有 OAuth 验证非流式请求和流式函数调用。
- 修复账号刷新旧快照覆盖、已删除账号复活、切号被撤销，以及活槽凭证已更新却误报失效。切号后旧回包不再锁住速度控件。
- Ultrafast 同时受账号权益和模型支持约束；无法明确确认权益时保留 Standard/Fast，不从普通 Pro 标签推断更高套餐。订阅用量不套用 API 定价。
- OAuth 在线目录优先使用当前账号实际返回的模型。统一思考档、上下文和模态参考来源，用户明确配置优先；扩充本地模型资料并新增 Meta 供应商入口。模型参考条目不保证每个账号或渠道均可调用。
- 附件交付兼容未使用字段中的空占位，参数错误和部分交付失败有具体说明。权限与路径检查仍然保留。
- 修复请求过大被帮助链接误判限流、没有重试却声称已重试、SOCKS 配置未变却刷新连接、远程卡片票据冲突、侧栏折叠偏好竞态和部分内部标签外露。更新界面区分功能内容与桌面外壳的更新状态。

## Compatibility and data notes

Persistent data remains on the existing data epoch. New state is additive or optional; existing session, OAuth vault, deferred-result, and activity formats remain readable. The activity retention policy intentionally removes expired completed history and its dedicated activity-session files. It is not a deletion policy for normal chats, scheduled-job definitions, or user-produced documents. Restoring old code does not automatically restore history that has already expired; back up existing history before enabling this build if it must be retained.

Records with neither a valid finish time nor a valid start time cannot be safely aged and are only subject to the completed-history count limit. Active/unknown states are preserved. Cleanup is access/write/startup driven, not a new periodic timer.

## Verification scope

Changes were verified in their corresponding local repair batches. The scroll batch passed 1,698 regression checks plus nine isolated browser geometry scenarios. Subsequent focused batches passed 25 checks for post-stop thinking settings, 30 for file delivery, and 18 for activity retention. These are overlapping batch results, not a cumulative unique-test count. Release preparation checks packaging metadata and direct release contracts rather than rerunning unrelated suites.

The Grok header follow-up passed 24 targeted checks. A live streaming OAuth probe completed with HTTP 200 and the expected function-call arguments; no tool was executed by that probe.

Release-digest and persistence-contract checks passed 56 targeted tests. The OAuth account vault's existing secret writer is now explicitly registered in the persistence inventory, and packaging fingerprints/closure metadata have been regenerated.

Full-project type checking has known outstanding diagnostics; this release preparation does not claim an all-green full-project type check. The open-export whitelist is also behind its dependency graph: the boundary lint reports 55 unregistered edges outside its tracked baseline. That check is not green, and its whitelist has not been loosened to mask the result. This build targets the existing Windows full-product composition; open-export validation remains outstanding. The original full-sidebar-expansion report was not fully reproduced; the confirmed preference races were fixed. Higher-tier OAuth entitlement positive cases were simulated rather than tested with a paid higher-tier account.
